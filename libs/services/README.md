# @project/services

Shared API contracts, route constants, validators, and service clients for the
Project monorepo.

## Installation

This is a private workspace package. Add it to the consuming workspace:

```json
{
  "dependencies": {
    "@project/services": "workspace:*"
  }
}
```

Then install dependencies from the repository root:

```sh
pnpm install
```

## Entry points

The package separates exports by where they are safe and intended to be used.

### `@project/services` (`index.ts`)

The main entry point contains code that can be shared across environments. Use
it for types, static values, API route constants, and validators.

It currently exports:

- authentication, document, item, legal, and service-response types
- `BACK_API_ROUTES`
- `LEGAL_DOCUMENT_IDS`
- `NotEmptyNumberValidator`, `NotEmptyStringValidator`, and `URLValidator`

```typescript
import {
  BACK_API_ROUTES,
  type AuthUser,
  type CreateItemBody,
  URLValidator,
} from "@project/services";
```

Prefer this entry point for shared contracts instead of importing files from
`src` directly.

### `@project/services/client` (`client.ts`)

This entry point is reserved for functions that may only be called in client
code. It is currently empty because the package has no client-only services.

When client-only functionality is added, import it from this entry point and
only use it in client modules or components:

```typescript
import { clientOnlyFunction } from "@project/services/client";
```

### `@project/services/server` (`server.ts`)

This entry point contains functions and service instances that may only be
called on the server. These functions commonly depend on environment variables,
credentials, or other server-side context and must not be imported into client
components.

It currently exports:

- `authService`
- `documentsService`
- `itemsService`

```typescript
import {
  authService,
  documentsService,
  itemsService,
} from "@project/services/server";

const result = await itemsService.list({ token });
```

The service methods use `BACK_API_BASE_URL` by default. A request can override
it with the `baseUrl` option and can pass a bearer token with the `token` option.

## Environment configuration

Environment variables are read from the application that consumes this
package. The package does not require a separate `libs/services/.env` file.

| Variable | Required | Description | Development default |
| --- | --- | --- | --- |
| `BACK_API_BASE_URL` | In production | Base URL used by the server service clients | `http://localhost:3001/api` |
| `NODE_ENV` | No | Controls production-aware validator behavior | Provided by the application |

## Available services

- `authService` handles the current user, profile, avatar, AI provider keys,
  legal acceptance, personal-data requests, and account deletion.
- `documentsService` lists, uploads, updates, downloads, and removes documents.
- `itemsService` lists, creates, updates, and removes items.

All standard JSON service calls return `StandardResponse<T>`. Methods that
transfer raw file content return a native `Response` where appropriate.

## Generating entry points

The root entry-point files are generated by `scripts/generate-index.ts`:

```sh
pnpm --filter @project/services generate-index
```

Run this command after adding or removing exported types, constants,
validators, or services. The generator currently builds:

- `index.ts` from `src/types`, `src/static`, `src/api-routes`, and
  `src/zod-validators`
- `server.ts` from `src/services`, excluding internal common service modules
- `client.ts` only after a client target is enabled in the generator

Do not manually maintain generated exports in `index.ts` or `server.ts`.
